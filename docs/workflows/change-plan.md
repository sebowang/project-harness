# Change Plan

## 目标

把非平凡需求转化为基于仓库事实、范围明确且可验证的实施计划。

## 步骤

1. 重述输入（`input`）、预期输出（`expected output`）、不可接受行为（`unacceptable behavior`）和可观察验收条件。
2. 检查相关源码、调用方、测试和文档。
3. 分开记录已验证事实、假设和未解决选择。
4. 定义范围、非范围和最小有效修改；跨越新的模块、所有权边界、公共契约或明显超出原计划时，说明无法进一步缩小的原因。
5. 识别可能变更的文件与兼容性风险。
6. 选择构建、测试、Harness 和手工验证证据。

不创建投机性抽象或无关清理。关键不确定性会改变实现时，暂停并请求决策。
